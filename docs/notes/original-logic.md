## Timing

One game tick = **60 ms** (`paint` case 104 busy-waits `< 60 ms`, ~16.7 Hz). All logic is integer and advances once per tick (`G_AdvanceGame`, line 2851). Port runs the engine at 16.667 Hz fixed step; the renderer may interpolate positions between ticks for smooth 60 fps (spec: pixel-art look is preserved).

## Coordinates and units

Positions are integer pixels, **tile = 16 px**: `u = x >> 4`, `v = y >> 4` (`Fighter.setX/setY`). A fighter's `(x, y)` is bottom-centre (feet). Fixed-point vertical speed `yspeed_fix` has 8 fractional bits (`>> 8`). Native view 176×192 + 16 px HUD panel = 176×208.

## Control bits (`man_presscommand`, `keyPressed`)

`bit = 1 << action`: action codes 1=up(unused), **2=jump**, **4=left**, **5=fire**, 6=down(unused), **8=action/down (lift, cycle)**. Resulting masks used by the engine: `0x02` jump, `0x04` left, `0x20` right (key 6), `0x40` action (key 8), `0x100` fire (key 5). Weapon select via `201/202/203` (keys `*`, `0`, `#`) sets `pendingweapon = 0/1/2`.

## Fighter (`Fighter.java`)

`MAXAMMO = {0, 99, 10}`. Weapons: **0 = saw (melee, infinite)**, **1 = laser pistol (battery ammo, max 99)**, **2 = bazooka (rockets, max 10)**. `canShoot(w) = w==0 || (weaponpresent[w] && ammo[w] > 0)`. `hp` max 100 (`r_hp_npoints = (hp+19)/20`), `armor` max 100. Colors 0 = blue, 1 = red; `ai_color_flag = 1 << color`.

## Movement (`G_MoveFighter`, line 2511)

- On ground: walk `xspeed = ±3` px/tick; no input → idle (`frame` cycles 0–24; walking cycles 25–36).
- Jump: `yspeed_fix = -2560` (−10 px/tick), `xspeed = ±3` (`setSpeed(3)`), `jumpthrust = true` while jump held.
- In air: `yspeed_fix += (!jumpthrust && yspeed_fix < 0) ? 768 : 256` each tick; `dy = yspeed_fix >> 8`, clamped to **[−10, 10]**; if clamped at 10 and `yspeed_fix > 2560` then `xspeed *= 2560 / yspeed_fix`. Air frame = 27.
- `hassupport = ispassenger || ((y & 0xF) == 0 && (cell[v][u] & 1) != 0)`.
- Ceiling hit: `y = (y+16) & ~15`, `yspeed_fix = 0`. Floor: `y &= ~15`. Fall below `mapheight + 40` ⇒ counts as death/suicide and respawn.
- Walls: horizontal move then if `cell[v-1][u] & 2` snap to tile edge, `xspeed = ∓1`, mark bump.
- While `busyindex > 0` (death animation) or dead: only fire bit is honoured / input zeroed; passengers only fire.

## Weapons (fire sequence in `g_fireseq`, `g_firemoment`)

| weapon | `weaponstate` frames (= reload) | fire moment | effect |
|---|---|---|---|
| 0 saw | 8 (`{7,7,7,10,10,10,9,9}`) | 5 | melee: `G_PickTarget` within 24 px, damage `U_Rnd(20, 50)`, blood |
| 1 laser | 5 (`{1,3,3,2,2}`) | 3 | hitscan range 96 px, ammo −1, damage `U_Rnd(10, 20)`; ray visible 4 ticks |
| 2 bazooka | 15 (`{4,4,4,4,11,11,11,11,6,6,6,6,5,5,5}`) | 12 | ammo −1, projectile type 56, speed **±5 px/tick**, max flight 96 px |

After a shot, if the current weapon cannot shoot any more, switch to `3 - w` if possible else the saw. Pending weapon applies only when `weaponstate == 0`. Muzzle offsets come from sprite part with sub-image 10 in each frame (`g_pistol_muzzlex/y`, derived in `G_Init` from `chars`; x clamped to ≤15, y = part_y + 1).

Projectile (`G_ThinkProj`, line 2797): moves `v` px/tick, dies out of map bounds; explodes when within 6 px horizontally of a living enemy fighter (y in `[fy-32, fy]`) or when passing its range limit `selfliq`. Splash: every living fighter within distance 22 px (box metric) takes `U_Rnd(60, 100)`, scaled by `(d - 6) / 16` when `d > 6`. Max 20 projectiles, 10 rays, 30 effect sprites.

## Damage and armor (`G_HurtFighter`, line 2253)

With armor > 0: `absorb = min(U_Rnd(dmg>>2, dmg - (dmg>>2)), armor)`; `armor -= absorb`; `hp -= dmg - absorb`. Death at `hp <= 0`: sound, `G_KillFighterCommon`, death animation sequence (`player_seqDie*`, violence option picks hard/very hard variants).

## Pickups (`G_MoveFighter` end, line 2682+)

- medikit (5): +25 HP, ignored if hp ≥ 100. armor (7): +25, ignored if ≥ 100.
- battery (8): +30 laser ammo, auto-switch to laser if had 0 ammo with saw selected.
- rocket (6): +2 rockets, auto-select bazooka if it couldn't shoot. bazooka (4): grants weapon + 2 rockets.
- Pickup radius: pobj within ±12 px of x and `data1 == v || data1 + 1 == v`. Respawn after 250 ticks (~15 s); queue handles ordering.

## Respawn (`G_RespawnFighterAt`, `G_RespawnFighter`)

hp 100, armor 0, weapons {saw, laser}, laser ammo 25, bazooka ammo 0, current weapon laser, drops flag. Spawn at node of `starts[idx]`; random index via `U_Rnd`; in DM re-roll once if equal to the last used spawn. Teleport fog effect. Death animation must finish first (`busyindex` countdown).

## Lifts (pobj types 1, 9, 12–19, 16)

3 consecutive pobjs form a shaft: anchor `n` (type 1/18/19 = idle/going down/going up) and stops `n+1`, `n+2`. At load one stop is randomly set to type 16 (car present) and the anchor's y is set to that stop. Pressing action (0x40) at a stop with a car boards (`ispassenger`); button type 9 calls it. Car speed ramps +1 px/tick² up to **14 px/tick**, braking by `g_brake_distance[s] = s(s+1)/2`. State machine: 12→13→(18/19 moving)→1 arrived, 14→15→16 settle & release passenger. Exact transitions: `G_AdvanceGame` lines 2868–2947. Port verbatim.

## Cycles (types 2, 3, `G_MoveCyclist`, line 2388)

Boarding at dock with action key while supported. Acceleration x: ±256/tick up to ±1792 (fixed ×256), y: ±256 up to ±1280, friction 128. Bounds from the map's cycle area. Fire = laser-like ray (range 96, damage `U_Rnd(20, 40)`, reload 10). Docking at either end when pushing outward near a dock node (|dy| < 16). Dead cyclist burns for 15 ticks then respawns.

## Tram (type 40, `g_tram_*`)

Active only if `tram_y > 0`. States: 0 idle (wait `U_Rnd(30,150)` ticks), 1 moving left, 2 moving right, 3 arrived. Speed ramps to 14 px/tick with brake distance table. Arrival kills (`G_Tram_Squish`) any grounded non-passenger fighter within 39 px at tram_y. Passenger carried at `tram_x`.

## DM rules

Frags: killer side `+1`; suicide (killer side == victim side) `−1`. Win when any side reaches `fraglimit` (`opt[21] * 5`, i.e. 0/5/10/… ; 0 = no limit). Player count `opt[9] + 1`; colors via `U_GenNonRepeating`.

## CTF rules (`G_TakeFlag`, `G_ReturnFlag`)

2v2 (`opt[18] == 1`) or solo. Touching enemy flag base (type 10/11) when enemy colour takes the flag (`iscarrying`, `g_flag_is_taken[side^1]`). Touching own base while carrying **scores 1** (`G_ReturnFlag(f, true)`). Per the help text a point is not given if own flag is also taken (the code path: own-base touch while own flag is taken does not trigger scoring because the flag marker is not at base). Death returns flag (`G_ReturnFlag(f, false)`). `fraglimit = opt[24]` (captures to win).

## Bots (`AI_*`, lines 1159–1637)

- Skill tables: `ai_reaction = {8, 40, 110, 178, 230}` (per-tick chance out of 256 to react/shoot), `ai_jumpiness = {10, 25, 50, 85, 110}` (chance out of 1024 to jump toward an enemy). Skill = `opt[6]` (0 very easy … 4 very hard).
- Navigation graph: nodes (type, x, y, left, right, top, flags). Bot keeps `ai_node_behind`/`ai_node_ahead`; picks next by `AI_RoamAimlessly` (random among left/right/top, never straight back), `AI_KeepBase`, `AI_MoveToFlag` (uses per-colour direction bits in node flags: `flags >> color` with bits 4/0x10/0x40 = left/right/top).
- Orders: `ai_order` 0 = defend, 1 = attack (go for enemy flag), 2 = roam (DM). Strategic decision (`AI_MakeStrategicalDecision`, every tick while `(tick & 0x100) == 0`, and on flag events): based on which flag is taken and bot positions.
- Combat: `AI_FighterShootsFighter` (±1 tile vertical window, ≤96 px, line-of-fire via `reachleft/right`), weapon choice by distance (<15 px saw, enemy hp<20 or has rockets → laser/bazooka logic), facing set toward target, fire when `U_RndBinary(255) < ai_reaction`.
- Movement bits: nodes of type 1/2/5/6/4/10/9 dictate left/right/jump/action (see `AI_ControlFighter`). Tram danger zones ±39 px (safe ±42).
- Ally control (CTF 2v2 only): player can set the ally's order (`X_AllyControlPossible`: mode CTF and 4 fighters). Orders menu: wait/defend (0), attack (1), and the third entry is as per `real.str` strings 69–71.

## RNG

`U_Rnd(n) = (nextInt & MAX_INT) % n`, `U_Rnd(a,b) = ... % (b-a+1) + a`, `U_RndBinary(m) = nextInt & m`. Port uses a seeded 32-bit PRNG with the same call structure; exact `java.util.Random` sequence is **not** reproduced (not observable by players).

## Options (`opt_options` indices)

0 violence, 3 no-medikits, 6 skill, 9 opponents (DM), 12 colour (DM), 15 colour (CTF), 18 2v2 flag, 21 frag-limit step (×5), 24 capture limit, 27 DM map (0–6), 30 CTF map (+7), plus defaults `{1,2,22,0,2,22,2,5,26,1,4,31,0,4,−1,0,2,−1,1,2,37,0,9,−1,0,10,−1,0,7,−1,0,5,−1}`.

## Rendering facts relevant to the port

- Frames: `chars` holds sub-images (sheet `m0..m3`, x, y, w, h), frame start table, and parts (sub, dx, dy). Frame `n` is left-facing, frame `n + 134` right-facing. Part sub-image `23` is a placeholder replaced by the weapon sprite from `g_fireseq`.
- Camera follows player: target `x − (headsleft ? 118 : 58)`, move ≤ 5 px/tick, y = `player.y − 112`, clamped to map. (Port: scale to the wide view, keep the look-ahead behaviour.)
- Effects: blood 3 variants, smoke, explosion, respawn fog (sequences in static init, lines ~3631–3649).
